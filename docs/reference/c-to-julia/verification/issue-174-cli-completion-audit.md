## Independent outputs and strict runner source bridge

`physcal_reference.rs` consumes existing offline
`tests/fixtures/physcal_181/two-samples/` references for real, complex and FSZ
Heisenberg and the labelled Hubbard DH/OptTrans harness. Existing native-C
Hubbard/spin Lanczos references retain their historical provenance; those
tests compare LS outputs in modes1/2.

The new
`all_hamiltonian_terms_cli_lanczos_matches_independent_base_and_corrected_outputs`
uses `tests/fixtures/physcal_181/hubbard_all_terms_lanczos1/` and
`hubbard_all_terms_lanczos2/`, including each `provenance.txt` and
`metadata-provenance.txt`. They record independently generated Julia1.13.1,
revision `8bb1b9e8ae47b1512c00b321be05664ddcac0fd1`, Linux x86_64,
OpenBLAS0.3.30 ILP64, Julia/BLAS threads1, seed1 and input/source hashes.
Their indexed layout follows C; they are not full native-C trajectory traces.
The test checks nonempty Transfer, CoulIntra, CoulInter, Hund, Exchange and
PairHop, absence of InterAll, and parsed Lanczos mode. It compares the complete
expected inventory: ordinary out/var and OneBodyG/TwoBodyG/TwoBodyGEx in both
modes, moments/LS energy in both modes, and corrected Green outputs in mode2.

Rows, columns and discrete index tokens are exact. Per-output budgets remain
those of `physcal_issue181::assert_reference`, using **max**, not sum:
moments absolute `1e-10`; other LS outputs absolute `1e-8`; ordinary
direct/factored Green absolute `1e-12`, relative `1e-9`; ordinary OneBodyG,
energy and var absolute `1e-12`, relative `1e-10`. Terminal whitespace is
trimmed: this is numerical/layout evidence, not byte-format validation.

The CLI calls `prepare_phys_cal_from_namelist_with_reducer_and_opt_trans`
and `vmc_phys_cal_with_reducer` with the selected seed, fixed input,
OptTrans and output path. Strict runner evidence uses these public APIs:

  `original_six_first_callback_boundaries_match_actual_runner_trajectories`
  and `remaining_original_two_sample_callback_boundaries_match_reference`.

  `two_sample_runners_match_independent_saved_states_rng_and_ordered_outputs`,
  `six_supported_physcal_models_preserve_fixed_values_flags_and_outputs`,
  and `all_six_non_interall_terms_match_independent_lanczos_modes`.
- Existing offline six-model records under `tests/fixtures/physcal_181/` and
  `two-samples/`: `fixed-parameters.txt`, `consumed-count.txt`, optimization
  flags, `initialized/{draw-count,next624}.txt`, and each
  `sample-i/{draw-count,next624,ele_idx,ele_cfg,ele_num,ele_proj_cnt,ele_spn,counter}.txt`.
  Model names: heisenberg_chain_real/cmp/fsz, hubbard_chain_real/dh_real,

These compare actual runner draw counts/next624 and discrete saved states to

## Launcher status evidence and retained failures

OpenMPI/OpenRTE metadata retains `--oversubscribe`; Hydra metadata selects
`-disable-auto-cleanup`. Unknown metadata fails explicitly, never skips.
Actual Hydra `mpiexec -help` documents that flag as “don't cleanup processes
on error”; captured in `hydra-help.log`. The outer45s timeout and5s forced
termination remain, and all negative nonzero/status/no-output assertions are
unchanged.

Retained initial failures: handle21876 terminal100 (metadata incorrectly
required uppercase MPICH); handle48306 terminal100 (2 PASS/1 FAIL);
handle4507 terminal100 (CLI rejection diagnostics but launcher exit0).
Logs `mpi-gates.log`, `mpi-gates-hydra.log`, `mismatch-diagnostic.log`.
Standalone libtest reproduced the latter observation, so it is not established
as nextest-specific (`mismatch-standalone.log`). The internal Hydra cause is
**not proved**, and no race-causality claim is made.

With cleanup disabled, the separate `-print-all-exitcodes` probe recorded
wait statuses256,256 (each rank exit1) and launcher exit1:
`rank-exits-no-cleanup.log`. Final three gates passed with strict failure
assertions. No launcher0 result was accepted as rejection evidence.

## Remaining completion boundary

All four criteria have bounded implementation/evidence mappings above.
Criterion4's strict RNG/config component remains a shared-public-runner
source bridge, **not direct subprocess observation**. Whole-model MPI numerical
parity and a full native-C sampler trace are not supplied by these CLI tests.
No acceptance claim is made for macOS MPI or the entire #179/#181/#185 scope.
Keep #174 open until the final integrated Linux milestone and parent audit
accept this explicit boundary.
