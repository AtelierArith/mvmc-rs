# Opt and PhysCal MPI comparison

From the repository root:

```bash
bash bench/run.sh
```

Runs native C, Julia and Rust for both variational optimization and fixed-parameter
physical measurements, then prints a Markdown table and saves `report.md`, raw
timings, logs, outputs and provenance in a new `bench-out/<timestamp>/` directory.
Default: periodic half-filled Hubbard chains L=32/64, t=1, U=4, 4 MPI ranks,
4 compute threads per rank, BLAS=1, 300 SR steps, 100 PhysCal groups,
300 saved configurations total per step/group, one warmup and three repetitions.
PhysCal uses the same parameters generated by the first measured C optimization
for all three implementations. Every PhysCal group saves `samples/ranks`
configurations per rank; group count and configuration count are separate controls.
Rust uses its production `calc-m-all` measurement path and C-order SR backend.
The selected measurement path is recorded in the report and environment metadata.
Inherited timer/diagnostic flags are cleared for the primary timing runs.

```bash
# Short end-to-end check, with both workloads and all three implementations:
bash bench/run.sh --sites 32 64 --steps 2 --groups 2 --samples 8 --reps 1
# Smaller serial run:
bash bench/run.sh --sites 16 --ranks 1 --threads 1 --steps 20 --groups 10
# Choose a new result location:
bash bench/run.sh --output bench-out/my-run
```

The short command verifies execution and reporting; use the default workload
for performance comparisons. The thread setting is the available compute pool,
not a claim that every kernel uses all workers. Small workloads can select serial
paths. Julia's separate warmed observation records actual sampled MVMC worker
participation in the logs and thread profiles.

Use the Linux Dev Container described in `docs/DEV_CONTAINER.md`, with Julia
1.13.1 installed using `.devcontainer/install-julia.sh`. Running from the host
automatically enters the one running Dev Container labelled for this repository.
The script uses `uv` for its Python orchestration. `--help` lists all controls,
including MPI prefix, Julia executable and an explicitly selected Julia source
checkout. The pinned `benchmark/julia_comparison/Manifest-v1.13.toml` is copied
into an isolated project and checked for changes after setup. Sources in `extern/`
are not edited; the native C source and build live inside the result directory.
Cargo follows the Dev Container's separate target/cache configuration.

Builds and runs are sequential. Do not run another heavy benchmark concurrently.
C timings use the rank-zero internal All timer after MPI initialization;
Julia/Rust timings use the maximum rank duration of a warmed production API,
including input parsing, parameter initialization/loading, sampling, SR or
observables, and output. Process startup, JIT, setup and warmups are excluded.
The report explicitly records these different timing boundaries. Timing/energy
results alone do not establish numerical or RNG parity.
