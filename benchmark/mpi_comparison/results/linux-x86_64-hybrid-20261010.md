# Julia / Rust MPI ハイブリッド比較（Linux x86_64、2026-10-10）

Julia 最適化の upstream PR: [julia-patch #72](https://github.com/tmisawa/Julia-mVMC/pull/72)。候補 commit: `0a17549534432db1e94cafe34ce40784a3b845b5`。計測時の未commit差分・hashは保存した環境JSONに記録し、このcommitの実行ソースと一致する。2026-10-10 に upstream main へ merge 済み（`7b1ffd519e24f1794807ad326e09ee49a6a8cd3f`）。参照submoduleはこのmerge commitへ更新した。以下の実測は保存された計測時sourceに対するもので、pin更新による再計測は行っていない。

300 SR steps、総 samples 300/step、warmup 1、reps 3。秒数は production API の最遅 rank の中央値。起動・JIT・warmup・実行観測は除外し、入力・初期化・最適化・出力を含む。重いビルドやテストと同時に計測していない。

全モデル・両実装で 4 processes × 1 thread が最速。Julia の短いコピーの並列起動を抑える変更は、L16 の 1×4 / 2×2 で約 5.6% / 6.9% の短縮。小さい差は3回の計測では確定的な改善とは判断しない。

## 環境・実行証拠

AMD Ryzen 9 PRO 8945HS、Linux x86_64 Dev Container、Rust 1.99.0、Julia 1.13.1、MPICH 4.2.0 /opt/mpich (ch4:ucx/Hydra/PMI1)。RustとJulia native helperはOpenBLAS 0.3.26 LP64、Julia LinearAlgebraはOpenBLAS 0.3.30 ILP64。どちらもCooperlake kernels。BLASは各process 1 thread。新フェーズではJuliaのILP64とnative LP64の両方を各rankで実測確認。最初のautoフェーズではLP64は環境指定と同一ライブラリの後続実測で確認した。

Julia は JULIA_NUM_THREADS=N,0、JULIA_MVMC_INNER_THREADS=1、JULIA_MVMC_PFAPACK_THREADS=0、GC threads=1。Profileで各rankのMVMC framesを実際に4 / 2 / 1 threadsで観測。Rustはparallel-pool entryを観測し、driver込みのJulia観測とは定義が違う。観測は計測外。auto/最適化フェーズのRust観測は初回warmup、pooledは追加20-step診断；各フェーズの実行ソース・バイナリhashを保存。Juliaはwarmup後の20-step診断。

UCX_ERROR_SIGNALS=SIGILL,SIGBUS,SIGFPE と UCX_MEMTYPE_CACHE=no を起動前に設定。[MPI.jlの既知問題](https://juliaparallel.org/MPI.jl/v0.13/knownissues.html)に従い、threaded GCのSIGSEGVとUCXの衝突を回避。MPIを別配布へ切り替えていない。

元Julia sourceは8d815db0eec0ba12dea88aa9edb3d5f74d7b5ccd。候補は独立clone target/bench/julia-hybrid-opt の専用branch。元submodule pin/manifestは変更していない。独立projectで既存Julia 1.13 lockを使いsystem MPICHを選択。

## 検証と制限

変更前後の9ケース・各20steps：SFMT初期/実行後の624-word状態ブロック42個が完全一致。出力の数値88794項目をabs=rel=1e-11で比較、最大絶対差0.0。浮動小数点bitwise比較はしていない。Julia unit testsは1-thread 22,008 / 4-thread 22,009 pass。Rust full nextestは1,583 pass / 87 configured skipped、check/clippy/fmt/doc、Python harness5testsもpass。

MPI process数を変えると独立chain seeds、warmup量、軌跡が変わる。処理速度の比較であり、統計的有効sample数や収束の証明ではない。三反復は小さな差や他ハードウェアでの効果を保証しない。新しい実測はLinuxのみ。
