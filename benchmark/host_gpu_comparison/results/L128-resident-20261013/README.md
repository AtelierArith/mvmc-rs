# Resident interval traffic at L128, 2026-10-13

Related to #560 and #550. This is a **sampling-only synthetic benchmark**, not
Hubbard Opt E2E and not a Rust/Julia optimization trajectory comparison.

Foundation source: `dc5d8625cc609f588267316dccb520906978fa94`.

The new ensemble-owned cuRAND and device-side rebuild schedule eliminate all
explicit `RawExec` transfers inside 20 sampling calls. They do not materially
improve the time of the already-batched interval kernel. The Opt measurement/SR
handoff and the arithmetic inside the kernel still need work.

## Results

FP64, L128, Ne64, 32 QP planes, 128 proposals per walker per call, 20 calls,
seed 79. Initial valid skew Slater matrices are generated by the test; there
are no projection terms. The initial state is restored for each repetition.
Median of repetitions 1–3; repetition 0 warms the kernel cache.

| Walkers | Host-controlled interval | Resident interval |
|---:|---:|---:|
| 64 | 4.951672 s | 4.908559 s |
| 320 | 17.603515 s | 17.765516 s |

The 320-walker resident result is about 0.9% slower in this cohort. No speedup
claim follows from removing these particular transfers. This does not measure
the old public per-hop sampler, whose round trips are much more frequent.

Explicit traffic for **320 walkers, all 20 calls**:

| Counter | Host-controlled interval | Resident interval |
|---|---:|---:|
| H2D calls | 58 | 0 |
| H2D bytes | 16,418,284 | 0 |
| D2H calls | 132 | 0 |
| D2H bytes | 423,808 | 0 |
| Stream synchronizations | 246 | 20 |
| Raw scopes | 96 | 20 |

Counters cover calls issued through `RawExec` on the calling thread, not
provider/library-internal transfers, barriers or launch arguments. Initialization
and final result downloads are outside the measured region. Each `advance`
still closes one synchronized raw scope. The baseline's host tapes are prepared
before timing; the resident timing includes generating those words on the GPU.

Both routes consume the same sequence of 20 cuRAND calls. Each repetition
checks exact final configurations and rebuild windows, plus Pfaffians with
`atol=rtol=1e-11`; all pass. The independent Julia RNG fixture separately checks
33,476 UInt32 words exactly. The independent historical Julia supplied-tape
fixture, persistent 20-call rebuild-boundary tests, full filling, mixed walkers,
failed rebuild publication and two-device checks gate this foundation.

## Environment and reproduction

NVIDIA GeForce RTX 3060, physical GPU 1, driver 580.178.04; Rust 1.99.0.
Standalone CUDA workspace test profile (`opt-level=2`), one BLAS/OpenMP thread.
Rust libraries: NVRTC 12.8.93, cuBLAS 12.8.4.1, cuRAND 10.3.9.90.
No other local build, test or benchmark ran during the measurement.

```sh
CUDA_VISIBLE_DEVICES=1 OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 \
LD_LIBRARY_PATH=/path/to/cuda-12.8-libraries \
timeout 1800 cargo nextest run \
  --manifest-path gpu/mvmc-gpu-cuda/Cargo.toml --test resident_interval \
  -E 'test(resident_l128_sampling_transfer_benchmark)' \
  --run-ignored all --no-fail-fast --retries 0 --test-threads 1 \
  --success-output immediate
```

`sampling.log` preserves all eight paired measurements, counters and assertions.
`kernel-sha256.txt` identifies the compiled CUDA sources. The recorded run
preceded two additional input-size guards in untimed preparation and one
different-device assertion; the measured CUDA code and sampling path were
unchanged. The post-change correctness run is `cuda-tests.log`. An earlier
gate invocation with the legacy L128 test's default 320-host-thread workload
was interrupted; the final gate explicitly uses 64 host walkers and the
existing short-interval input. This is distinct from the **320 device walkers**
tested in the resident benchmark, which require only one host owner.

The new `ResidentInterval` is currently a library primitive. The public Opt
runner has not been switched to it; its public E2E time must be remeasured after
resident measurement/SR integration. The historical public comparison remains
[47.8588 s Rust / 5.12493 s Julia](../L128-opt-20261012/README.md).
