# Resident PhysCal window statistics (#729)

Linux x86_64 / RTX 3060, 2026-11-12. The warmed public API shows no measurable
regression in these three configurations with window Green history disabled.
The largest upper end of the paired timing interval is +0.79%; these runs do
not establish a universal zero-overhead claim or A100 performance.

| Case | Walkers × windows | Before median | After median | Median change | Paired mean change, 95% interval |
| --- | ---: | ---: | ---: | ---: | ---: |
| L16 | 64 × 20 | 99.021 ms | 98.935 ms | −0.086% | [−1.467%, +0.708%] |
| L128 | 64 × 20 | 1597.046 ms | 1595.965 ms | −0.068% | [−0.201%, +0.039%] |
| L128 API default ensemble/window count | 320 × 1 | 562.198 ms | 562.523 ms | +0.058% | [−0.150%, +0.788%] |

Each worker excludes one full warmup API call, then performs nine timed calls
with fresh inputs/state and seed 79. The before/after order alternates between
pairs. Warmup and interval are both 128 proposals per walker. The API timer
includes parsing, parameter loading, initialization, sampling, observation and
final downloads; worker file output is outside the timer. Both worker processes
are pinned to CPU 17, run sequentially on physical GPU 1 (CUDA ordinal 0), and
use one BLAS/OMP thread. GPU clocks are unlocked. The paired interval is the
Student-t interval (8 degrees of freedom) for the mean log(after/before),
exponentiated back to percentage change; it describes timing variation.

The comparison checks every existing returned energy/Green value with
`atol=rtol=1e-12`; the observed maximum absolute difference was zero. This is a
same-input implementation regression check, not a C/Julia physics oracle.
Independent per-configuration CPU C-order moment checks are in the CUDA tests.

All cases retain 27 upload calls, 3 download calls, 11 synchronizations and
8 raw-execution scopes. Uploaded bytes are unchanged. Energy histories add
exactly 24 bytes per window to the final download, with no per-window transfer:

| Case | Before download bytes | After download bytes |
| --- | ---: | ---: |
| L16, 20 windows | 1040 | 1520 |
| L128, 20 windows | 8208 | 8688 |
| L128, 1 window | 8208 | 8232 |

Before source: `9ffe7141b65a5f91fa00708a7f563b64630d2777` (the #728 branch;
its source tree was merged as `58ee435f`). After source:
`3c8a09c5` (full SHA and source hashes in `results/summary.json`). Both are
standalone default-feature `--release --locked` builds with the same lock.
The before executable was saved before editing the production code.
Rust/compiler, binary hashes, linked libraries, image ID, GPU/driver and raw
worker logs are in `results/`. The device backend is cuBLAS 12.9.2, with
NVRTC 12.9 and cuSOLVER 11.7.5, driver 580.178.04 (driver API 13.0).
The linked CPU OpenBLAS path is recorded by `ldd`; it is not the device backend.

L128 uses the existing `benchmark/cpu_scaling_l128/inputs/phys` inputs and
fixed parameters. L16 copies `benchmark/hubbard_chain/inputs/hubbard_chain_L16`,
with `NVMCCalMode=1`, `NVMCWarmUp=0`, `NVMCSample=8`; the worker explicitly
overrides sampling lengths. `inputs/l16-params.dat` preserves the exact timing
input generated by the #728 CLI smoke run (8 walkers, 2 steps, seed 79,
warmup/interval 0). It is Rust-generated input for timing, never a numerical
expected-value fixture. Its unavailable header diagnostics are ignored by
the parameter reader. All input hashes are retained in the summary.

## Reproduction

Build `resident_physcal_worker` at the two recorded revisions, using separate
checkouts and Cargo targets. The CUDA container and mounts follow the existing
`benchmark/gpu_followup_733/README.md` workflow. Save each executable under a
distinct path visible inside the container; the runner never rebuilds them.
Both binaries must use the same CUDA libraries and physical device selection.

Prepare the L16 directory (new scratch path):

```sh
mkdir -p target/reproduce729/l16
cp benchmark/hubbard_chain/inputs/hubbard_chain_L16/*.def target/reproduce729/l16/
sed -i 's/NVMCCalMode    0/NVMCCalMode    1/; s/NVMCWarmUp     10/NVMCWarmUp     0/; s/NVMCSample     300/NVMCSample     8/' target/reproduce729/l16/modpara.def
uv run --no-project python benchmark/gpu_physcal_windows_729/run_paired.py \
  /work/path/to/before-worker /work/path/to/after-worker \
  target/reproduce729/paired --container YOUR_CUDA_CONTAINER \
  --l16-input target/reproduce729/l16/namelist.def \
  --l16-params benchmark/gpu_physcal_windows_729/inputs/l16-params.dat
```

The container must mount this checkout at `/work`, expose the chosen GPU as
ordinal 0, and provide the CUDA/BLAS libraries. `--cpu` defaults to 17; choose
an allowed CPU on another host and record it. Use a new output directory.
The runner records raw logs, timed results, input hashes, means comparison,
transfer counters and paired ratios. Reproduced results retain their own
source/environment identifiers rather than replacing these recorded results.
